# 화이트·블루와 결정 룰렛 디자인 제안

작성: 2026-09-29 · 상태: 구현 전 디자인 산출물

시안: [blue-roulette-mockup.html](blue-roulette-mockup.html). 외부 의존·네트워크·실제 앱 데이터 연결이 없는 HTML이다. 살 것, 고민 중, 작은 룰렛 팝업을 함께 비교하고 라이트/다크, 320dp, 큰 글씨, 준비/회전 중/두 결과를 전환할 수 있다. 제품 코드는 이 디자인 작업에서 수정하지 않는다.

## 1. 방향과 기존 화면과의 관계

사용자 요구는 전체 초록 UI를 화이트와 자연스럽고 과하게 쨍하지 않은 블루로 바꾸고, 각 고민 항목의 ‘살래요’ 옆에 ‘결정할래요’를 추가하는 것이다. 팝업은 살래요/안 살래요를 각각 50%로 결정하며, 살 것으로 이동 또는 삭제로 이어진다.

현재 v1.2.0의 `ShoppingContent.kt`가 실제 시작 화면·탭·항목 행을 그린다. 그 안의 private `ShoppingRow`가 변경의 중심이다. `ItemRow.kt`와 `design/DESIGN.md`, 기존 `design/qa`는 구형 시각 규칙의 참고 자료이며, 실제 동선은 `docs/superpowers/specs/2026-09-26-shopping-first-ux-design.md`와 현행 코드에 맞춘다.

디자인 선택은 다음과 같다.

- 바탕은 흰색에 가까운 차가운 뉴트럴, 항목 그룹과 팝업은 흰색. 전체 면적을 파란색으로 칠하지 않는다.
- `#37658C`를 선택·체크·핵심 버튼에 사용한다. 짙고 채도를 낮춘 블루여서 흰 바탕에서 읽기 쉽다.
- 고민 항목은 이름/수량/더보기와 액션을 두 단으로 나눈다. 두 버튼은 이름 아래 나란히 두어 ‘옆에’ 관계를 유지한다.
- 룰렛에 카지노 효과·색종이·반짝임·소리를 넣지 않는다. 물건 결정의 보조 동작이라는 무게를 유지한다.
- 안 살래요는 실패가 아니므로 룰렛의 절반을 위험 빨강으로 칠하지 않는다. 실제 삭제 메뉴·오류만 기존 error 의미를 유지한다.

## 3. 화면 규격과 버튼 계층

기존 ‘무엇을 살까요?’, 목록 선택, 탭 개수, 진행률, 구매 완료 접기, 빠른 입력 동선을 유지한다. 상단 상태와 시스템 인셋은 OS에 맡긴다.

| 요소 | 규격·동작 |
|---|---|
| 기준 화면 | 390dp 폭. 360dp와 320dp에서도 검토 |
| 콘텐츠 좌우 여백 | 일반 20dp, 320dp 좁은 화면 16dp |
| 제목 | 기존 headlineLarge. 폰트 체계는 유지 |
| 그룹 표면 | surfaceCard, radius 18dp, 내부 좌우 10dp |
| 살 것 행 | 기존 64dp 이상, 독립 체크 48dp, 이름 탭 편집 유지 |
| 고민 중 행 | 고정 높이 금지. 기본 약 120dp, 이름·수량·더보기 48dp 이상 + 버튼 48dp 이상 + 여백 |
| 이름 | 기존 titleMedium 18/24sp SemiBold, 기본 2줄. 접근성에는 전체 이름 제공 |
| 더보기 | 48×48dp. 기존 수정/이동/삭제 메뉴 유지 |
| 행 사이 구분선 | outlineVariant 1dp; 각 항목을 큰 외곽 카드로 재분할하지 않음 |
| 버튼 간격 | 8dp. 줄 바꿈이 필요하면 세로 8dp |
| 살래요 | FilledTonalButton, primaryContainer/onPrimaryContainer, 높이 48dp 이상, radius 12dp |
| 결정할래요 | OutlinedButton, primary 글자, outline 1dp, radius 12dp, 높이 48dp 이상. 선택적 룰렛 아이콘 18dp |
| 돌리기 | FilledButton, primary/onPrimary, 전체 가용 폭, 높이 48dp 이상, radius 14dp |
| 준비 상태 닫기 | 텍스트 버튼 또는 우상단 48dp 닫기. 회전·반영 중에는 비활성 또는 숨김 |
| 결과 확인 | 기존 시작 버튼 위치의 FilledButton. 재돌리기 없음 |

‘살래요’를 자주 쓰는 직접 동작으로, ‘결정할래요’를 선택 가능한 보조 동작으로 보이게 한다. 두 버튼을 모두 진한 채움으로 만들지 않는다. 기본적으로 ‘살래요’는 왼쪽, ‘결정할래요’는 오른쪽이다. 가로가 부족할 때 아이콘을 먼저 생략할 수 있지만 텍스트를 ‘결정’으로 줄이거나 말줄임하지 않는다.

살 것에 이동한 뒤 현재 ‘고민 중’ 탭을 유지한다. 자동 탭 전환으로 다음 고민 물건을 찾는 흐름을 끊지 않는다. 완료 구매로 체크하지 않는다. 같은 이름의 항목을 임의 병합하지 않는다.

## 4. 작은 룰렛 팝업

- 모달 폭 `min(가용 폭 - 48dp, 340dp)`. 320dp 화면에서는 좌우 16dp로 완화하여 288dp. radius 26dp, 내부 좌우 22dp(좁으면 18dp).
- 높이는 내용에 맞추고 화면 안전 영역 안에서 세로 스크롤한다. 고정 높이로 큰 글씨를 자르지 않는다. 하단 실행/확인 버튼은 스크롤로 항상 도달 가능하다.
- 제목 ‘가볍게 결정해볼까요?’ 아래에 대상 물건 이름을 표시한다. 수량은 필요 시 이름 옆 또는 다음 줄에 `×2`. 물건 이름은 2줄까지 표시하고 전체 이름을 접근성으로 제공한다. 큰 글씨에서도 제목·안내·결과 영역은 필요한 높이를 확보한다.
- 시작 전 문구: **‘각 50% · 결과에 따라 이동하거나 삭제해요’**. 보조 설명: **‘살래요는 살 것으로, 안 살래요는 삭제돼요. 팝업을 닫은 뒤 실행 취소할 수 있어요.’**
- 룰렛 지름 200dp, 영역 확보 높이 약 216dp. 좁거나 낮은 화면에서 176dp까지 줄일 수 있지만 글자와 반반 구조는 유지한다. 기본 텍스트 14sp 이상, 섹터 내 50%는 12sp 이상. HTML의 축소 보드는 설명용이며 Android 글자 크기의 기준은 이 문서다.
- 삼각 포인터는 12시 방향 고정, 20×22dp. 회전 디스크 위로 겹치고 배경과 대비되는 `roulettePointer`. 외곽 4dp 표면 링, 중앙 30dp 허브.
- 두 영역은 각각 정확히 180°다. 면적·반지름·텍스트 무게가 같아야 한다. 영역마다 ‘살래요 50%’, ‘안 살래요 50%’를 직접 표시한다.

### 상태와 복사 문구

| 상태 | 본문·버튼 | 닫기와 저장 |
|---|---|---|
| 준비 | 설명 + ‘돌리기’, ‘지금은 닫기’ | 닫기/뒤로/바깥 터치 모두 변경 없이 닫음 |
| 회전 중 | ‘어떤 결과가 나올까요?’ + 비활성 ‘돌리는 중…’ | X/바깥 터치/뒤로/취소를 차단. 한 세션을 끝까지 유지 |
| 반영 중 | 정지한 결과 + ‘반영 중…’ | 저장 요청은 한 번만. X/바깥 터치/뒤로/취소 차단 |
| 성공: 살래요 | ‘살래요’ / ‘살 것으로 옮겼어요.’ + ‘확인’ | 결과 자동 적용 완료. 팝업은 읽을 수 있게 유지 |
| 성공: 안 살래요 | ‘안 살래요’ / ‘고민 중에서 삭제했어요.’ + ‘확인’ | 결과 자동 적용 완료. 팝업은 읽을 수 있게 유지 |
| 실패·대상 변경 | ‘반영하지 못했어요’ / 현재 상태에 맞는 설명 + ‘닫기’ | 성공 문구 금지. 무조건 재추첨하거나 중복 요청하지 않음 |

결과 팝업에 재돌리기를 두지 않는다. 결과를 정한 뒤 별도 ‘적용’ 버튼도 만들지 않는다. 결정과 실제 변화가 어긋나지 않게 자동 반영하되, 완료한 결과는 ‘확인’으로 닫을 때까지 읽을 수 있다.

닫힌 뒤 기존 snackbar host에 항목 이름과 ‘살 것으로 옮겼어요’ 또는 ‘삭제했어요’를 표시하고 ‘실행 취소’를 연결한다. **팝업 뒤에서 snackbar를 먼저 시작하지 않는다.** 실행 취소 토큰은 해당 동작의 것을 보관한다. 다른 행·다른 동작을 되돌리면 안 된다. 결과 팝업에서 뒤로·닫기·바깥 터치로 나간 경우도 같은 안내를 시작한다.

## 5. 룰렛과 실제 결과 일치

구현 좌표는 Android Canvas의 3시 0°, 시계 방향 증가 기준이다. BUY는 시작 -90°, sweep 180°의 **오른쪽 반원**이고 SKIP은 왼쪽 반원이다. 포인터는 항상 12시에 고정한다. HTML 시안도 같은 좌우 섹터와 정지각을 사용한다. CSS conic-gradient는 12시 0°이므로 색 영역만 CSS 좌표에 맞춰 정의하며, 회전값은 아래와 동일하다.

1. 사용자가 시작할 때 `BUY` 또는 `SKIP`을 50:50으로 **한 번** 뽑아 해당 실행에 고정한다. 시각 애니메이션의 프레임 수·닫기 시점으로 결과를 계산하지 않는다.
2. 정지각은 `360° × 5 + (BUY 270° / SKIP 90°) + jitter`로 한다. 결과 영역 중심이 12시에 도착한다. jitter는 구현 계획의 최대 ±60° 이내이며 섹터 경계에 닿지 않는다. HTML은 ±28°를 사용한다. 결과 확률은 jitter와 독립이다.
3. 회전은 **2800ms**, 약 5바퀴, 빠르게 시작해 부드럽게 멈춘다. 회전 중 재탭은 무시한다. 자동 무한 회전은 사용하지 않는다.
4. 저장 동작과 결과 문구는 위에서 고정한 enum을 사용한다. 표시된 정지각을 거꾸로 해석하여 새로 결과를 추정하지 않는다.
5. 라벨은 휠과 함께 이동하되 읽는 방향을 보정할 수 있다. 결과 텍스트는 별도의 고정 영역에 둔다.

구현 검증에서는 두 고정 결과와 정지각 최솟값/최댓값을 넣어 포인터가 정확한 반원에 놓이는지 확인한다. 임의 추첨을 수백 번 돌리는 것만으로 시각적 일치를 입증하지 않는다.

## 6. 취소·중복·생명주기

- 팝업은 한 번에 하나다. 빠른 연속 탭으로 같은 항목의 세션이 둘 생기지 않는다.
- **시작 전 준비 상태에서만 변경 없는 취소가 가능하다. 회전·반영 중에는 X, 바깥 터치, 뒤로 가기, 취소 버튼으로 닫을 수 없다.** 중복 시작도 차단한다.
- 목록별 ViewModel이 대상 item/list ID, 시작 시점 스냅샷, 실행 ID, 고정 결과, 목표 각도와 진행 상태를 소유한다. Compose 재구성·Activity 재생성 시 재추첨하거나 재적용하지 않는다.
- 앱이 잠깐 배경으로 가거나 화면이 재생성되어도 같은 세션을 유지한다. HTML의 visibilitychange를 이용한 자동 취소는 사용하지 않는다. Android 프로세스가 종료되면 미완료 룰렛은 취소되어도 되지만 이미 저장된 변경은 유지하고 재시작 때 재적용하지 않는다.
- 저장은 Repository의 단일 트랜잭션에서 시작 시점 스냅샷과 현재 항목을 비교한 뒤 한 번만 수행한다. 다른 항목·다른 목록에 결과가 적용되지 않는다. 대상이 삭제·수정·이동되었다면 변경하지 않고 오류를 표시한다.
- 저장 성공 전에 ‘옮겼어요’, ‘삭제했어요’를 말하지 않는다. 실패 시 원래 추첨 결과의 저장 재시도 또는 닫기를 제공할 수 있다. 재시도가 난수를 다시 뽑아서는 안 된다.
- 삭제·이동은 기존 정책과 `UndoToken`을 반환하는 일회성 결과 적용 API로 연결한다. 성공 결과 팝업을 닫은 뒤 해당 토큰의 실행 취소 안내를 한 번만 전달한다.
- 결과 상태의 X/뒤로/바깥 터치는 취소가 아닌 닫기다. 적용된 결과는 유지하고 동일한 snackbar 안내를 시작한다. 실행 취소를 누르면 원래 고민 항목을 복원한다.

## 7. 작은 화면·큰 글씨·접근성

- 320dp에서도 두 버튼의 최소 터치 영역 48dp를 유지한다. 이름의 남은 폭을 두 버튼이 빼앗지 않는다.
- 큰 글씨에서 두 버튼 전체 너비가 가용 폭을 넘으면 버튼을 세로로 쌓고 둘 다 전체 폭으로 만든다. 특정 fontScale 숫자만 검사하기보다 실제 측정된 콘텐츠 기준으로 전환하는 것이 좋다.
- 이름·상태·결과는 고정 높이에 가두지 않는다. 팝업 제목, 대상, 안내, 결과, 확인 버튼 모두 세로 스크롤로 접근할 수 있어야 한다. 200% 글씨 배율과 가로 화면에서 확인한다.
- 라이트와 다크 모두 버튼 글자와 상태를 색만으로 구분하지 않는다. 선택 탭은 표면 변화·굵기·선택 semantics를 함께 사용한다.
- TalkBack으로 각 행 버튼은 ‘무선 이어폰 살래요’, ‘무선 이어폰 결정할래요’처럼 물건명을 포함한다. 아이콘은 장식으로 중복 낭독하지 않는다.
- 모달 열기 시 제목/대상으로 포커스를 안내하고 배경 항목의 탐색을 차단한다. 닫기 후 해당 행이 남아 있으면 원래 버튼으로, 사라졌으면 가까운 항목 또는 결과 안내로 포커스를 옮긴다.
- 휠 자체를 여러 접근성 노드로 쪼개지 않는다. ‘살래요 50%, 안 살래요 50%’를 한 번 안내한다. 애니메이션 매 프레임을 읽지 않는다.
- 결과는 live region으로 한 번 알리고 읽기 시간을 제한하지 않는다. 접근성 사용자가 확인한 뒤 snackbar의 실행 취소 기회가 시작된다. snackbar 유지 시간은 Android 접근성 권장 시간에 따른다.
- 모션 감소/애니메이션 배율 0에서는 회전을 생략 또는 짧은 페이드로 대체한다. 확률·정지 결과·자동 반영 동작은 동일하다. 소리·연속 햅틱은 넣지 않는다.
- 키보드 포커스 표시와 스위치 액세스를 제공한다. 준비/결과 상태는 뒤로 가기로 닫을 수 있고, 회전/반영 중에는 진행 상태를 안내하며 닫기를 차단한다. 결과가 이미 반영된 상태의 뒤로는 취소가 아닌 닫기다.

## 8. 전체 앱에 적용할 범위

| 파일/영역 | 디자인 적용 |
|---|---|
| `ui/theme/Color.kt` | 전역 light/dark 슬롯 및 surfaceCard 유지 |
| `ui/theme/Theme.kt` | 고정 팔레트 선택 확인. dynamic color를 새로 켜지 않음 |
| `ui/components/ShoppingContent.kt` | 고민 행 2단과 새 callback. 현재 private ShoppingRow가 실제 대상 |
| 새 `ui/components/DecisionRouletteDialog.kt` 제안 | 작은 팝업, equal sectors, 상태·접근성·모션 |
| `ui/screens/ListScreen.kt` | 팝업 결과 안내와 실행 취소를 기존 host에 연결 |
| `ui/screens/ShoppingHomeScreen.kt` | 공용 ShoppingContent 시그니처와 초안 상태 연결 확인 |
| 목록 전환/편집/관리/살림 계획 | ColorScheme 상속 확인. 하드코딩된 초록만 제거 |
| `ui/components/ItemRow.kt` | 구형 경로 사용 여부 확인 후 기존 theme 상속만 검토. 새 기능을 이곳에만 붙이지 않음 |
| `res/values/themes.xml`, `res/values-night/themes.xml` | 스플래시 배경 light `#F7F9FC`, dark `#121922` |
| `res/drawable/ic_launcher_background.xml` | 밝은 배경 그라데이션 `#ECF3FA` → `#DCE8F4`; 기존 밝은 원형 면은 유지 |
| 런처 adaptive foreground/monochrome | 기존 장보기 심볼의 path/shape를 유지. 녹색 주형상 → `#37658C`, 옅은 녹색 fill → `#BFD5EA`/`#A9C6E2`, 작은 강조 → `#D8E8F7`. monochrome 참조 확인 |
| `res/values/colors.xml` 및 기타 아이콘 배경 리소스 | 실제 참조되는 초록 상수 탐색 후 동일 블루 적용 |

`Type.kt`의 기본 크기와 글꼴은 유지하고 레이아웃에만 필요한 대응을 한다. 이 팔레트 변경에 이미지 생성이나 새 브랜드 심볼은 필요 없다.

## 9. 산출물 검증과 구현 전 확인

이번 산출물은 디자인 문서와 독립 HTML만이다. 색 대비는 Node로 계산했다. HTML JavaScript의 파싱·DOM 없는 보조 검증과 외부 의존 여부를 확인한다. 브라우저 도구가 `file:` URL을 보안 정책상 차단하여 렌더링 스크린샷 및 실제 브라우저 상호작용 검증은 이 작업에서 완료하지 못했다. 제한을 우회하는 다른 경로는 사용하지 않았다. 따라서 Android 기기 렌더링·접근성·빌드가 검증됐다고 간주하지 않는다.

구현 후 필수 시각 확인은 light/dark의 살 것·고민 중, 긴 항목명, 320dp·200% 글씨, 두 결과의 포인터 일치, 준비 상태 취소, 회전/반영 중 닫기 차단, 빠른 재탭, Activity 재생성 시 세션 유지, 결과 유지와 닫은 뒤 snackbar, 이동/삭제 실행 취소, 시작·스플래시·런처의 초록 잔존 여부다.
