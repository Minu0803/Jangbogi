# 물건 중심 장보기 UX·UI 개편 설계 초안

작성: 2026-09-26 · 기준: main / 7330ae6 · 상태: 사용자 검토 전 제안

## 1. 목적과 확인된 요구

- 앱을 열면 기존 목록 상세에 해당하는 ‘무엇을 살까요?’ 화면에서 바로 물건을 입력하고 확인한다.
- 목록 생성·이름 입력을 시작 조건에서 제거한다. 여러 장보기 목록은 계속 지원한다.
- **각 장보기 목록 안에서** ‘살 것’과 ‘고민 중’을 구분한다. 공통 고민함은 만들지 않는다. 사용자가 직접 선택한 범위다.
- 동선과 시각 디자인을 함께 개선한다. 사용하기 쉽고 정돈된 인상을 목표로 한다.
- main에서 작업한다. 모든 커밋은 사용자 허락 후 진행한다.
- 이번 산출물은 계획과 화면 시안이다. 앱 구현은 이 제안 검토 후 시작한다.

## 3. 접근 방식 비교

| 방식 | 장점 | 한계 | 판단 |
|---|---|---|---|
| A. 선택한 목록을 홈으로, ‘살 것 / 고민 중’ 전환 | 입력·체크에 집중, 목록별 고민 보관이 명확 | 고민 항목 내용은 한 번 전환해야 보임 | **추천**. 항상 개수를 표시해 발견성 보완 |
| B. 선택한 목록의 살 것·고민 중을 한 화면의 두 구역으로 표시 | 두 종류를 함께 볼 수 있음 | 목록이 길면 고민 구역이 아래로 밀림 | 시안으로 비교 제공 |
| C. 전체 목록의 물건을 하나의 통합 홈에 표시 | 전체 물건을 한눈에 볼 수 있음 | 입력할 목록·같은 이름의 물건·구매 맥락이 모호 | 첫 개편에서는 제외 |

아래 설계·구현 초안은 A를 기준으로 한다. B 선택 시 화면 구성 계획을 수정하고 구현한다. 레이아웃 선택 설정 자체를 앱에 추가하지 않는다.

## 4. 추천 화면 구조

```text
주말 장보기 ▾                         살림 계획

무엇을 살까요?
4개 남았어요 · 2/6 구매 완료
──────── 작은 진행 표시 ────────

[ 살 것 4             ][ 고민 중 2           ]

채소
○  대파                   ×1           ⋯
○  양파                   ×2           ⋯

유제품
○  우유                   ×2           ⋯

구매 완료 2                             펼치기

자주 담는 물건              두부   바나나
[ 살 물건을 적어보세요                  ][담기]
```

- 상단 목록명은 목록 전환 시트를 연다. ‘새 목록’과 ‘목록 관리’도 여기서 찾는다.
- 제목은 첫 화면에 노출하되 스크롤·키보드가 열릴 때 공간을 줄인다. 앱 실행만으로 키보드를 띄우지 않는다.
- ‘살 것’ 개수는 미완료 구매 확정 항목 수, ‘고민 중’ 개수는 미결정 항목 수다. 수량 합계가 아닌 품목 행 수다.
- ‘구매 완료’는 살 것 화면 아래에 기본 접힘으로 표시한다. 펼쳐서 구매 취소할 수 있다.
- 살림 계획은 상단의 명시적인 보조 진입점으로 유지한다. 1차 개편에 하단 내비게이션은 추가하지 않는다.
- 목록 관리·살림 계획 화면에도 같은 타이포그래피, 색상, 표면 규칙을 적용한다.

## 5. 시작 및 목록 선택

1. 신규 사용자는 빈 ‘내 장보기’ 화면에 도착한다. 별도 목록명 입력 없이 물건을 추가할 수 있다.
2. 첫 유효한 항목 저장 시 목록 생성과 항목 저장, 활성 목록 저장을 하나의 트랜잭션으로 처리한다. 빈 입력이나 화면 방문만으로 목록을 만들지 않는다.
3. 재실행 시 마지막으로 선택한 유효한 목록을 연다. 완료된 목록이라도 사용자가 선택했다면 유지한다.
4. 기존 사용자 또는 활성 목록이 삭제된 경우: 미완료 ‘살 것’이 있는 가장 최근 목록 → 가장 최근 목록 → 빈 ‘내 장보기’ 순서로 선택한다. 날짜 동률은 id 내림차순으로 결정한다.
5. ‘새 목록’은 이름 없이 바로 빈 작성 화면으로 들어간다. 첫 저장 때 날짜형 기본 이름을 사용하며 이름 변경은 선택 사항이다. 기존 활성 목록을 새 목록으로 덮어쓰지 않는다.
6. 목록 전환 시 해당 목록의 ‘살 것’ 보기로 진입한다. 다른 목록의 고민 항목은 섞이지 않는다.
7. 목록 변경 때 입력 중인 내용은 목록 id별 SavedStateHandle에 보존한다. 새 목록 초안도 별도의 draft 키를 사용한다.
8. 목록 삭제 확인에는 살 것·고민 중·구매 완료가 함께 삭제된다는 사실을 표시한다. 삭제 취소는 세 상태를 전부 복원한다.

## 6. 입력·편집·구매 동작

- 하단 입력창은 현재 보기와 같은 대상으로 저장한다. ‘살 것’에서는 ‘담기’, ‘고민 중’에서는 ‘보관’으로 표시한다.
- 입력창 위에 현재 대상 ‘살 것에 추가’ / ‘고민 중에 보관’을 표시해 저장 위치가 숨겨지지 않게 한다.
- 기존 `우유 2`, `사과 x3` 수량 파싱, 카테고리 자동 분류, 자주 담는 물건 추천을 유지한다.
- 입력 후 키보드와 포커스를 유지하며 연속 입력한다. 처리 중 중복 제출을 막고, 성공 후 입력을 비운다. 실패하면 입력을 유지하고 재시도를 제공한다.
- 체크 영역 48dp 이상: 구매 완료/취소. 이름 영역: 편집. 더보기: ‘고민 중으로 이동’ 또는 ‘살 것으로 이동’, 삭제. 길게 누르기는 필수 동작에서 제외한다.
- 고민 항목은 구매 체크 대신 **‘살래요’** 버튼을 제공한다. 누르면 같은 목록의 ‘살 것’으로 이동한다. 현재 탭을 유지하고 이동 안내와 실행 취소를 표시한다.
- 살 것 → 고민 중은 더보기에서 이동한다. 구매 완료 → 고민 중도 가능하며 구매 완료 표시를 해제한다.
- 편집 기본 영역은 이름, 수량, 카테고리다. 구매 날짜·매장·기한·비축 월·재고는 ‘구매 계획·재고’ 접기 영역으로 묶는다. 기본 정보 저장 버튼은 키보드 위에서도 접근 가능하게 한다.
- 스와이프 삭제는 보조 기능으로 유지하되 더보기의 삭제와 동일한 실행 취소를 제공한다.
- 삭제·이동 안내는 저장 성공 뒤 표시한다. 실행 취소는 해당 동작 토큰을 사용하여 빠른 연속 동작에서도 다른 항목을 되돌리지 않는다.

## 7. 항목 상태·중복·집계

### 저장 모델

`ShoppingItem`에 `purchaseIntent: PurchaseIntent = BUY`를 추가한다. 값은 `BUY`, `CONSIDER` 두 가지다. 기존 `isChecked`, `checkedAt`는 유지한다.

| 사용자 상태 | purchaseIntent | isChecked | checkedAt |
|---|---|---|---|
| 살 것 | BUY | false | null |
| 고민 중 | CONSIDER | false | null |
| 구매 완료 | BUY | true | 완료 시각 |

- CONSIDER는 직접 체크할 수 없다. ‘살래요’로 BUY가 된 뒤 체크한다.
- 이동은 기존 행의 의도만 바꾼다. id, 이름, 수량, 카테고리와 구매 계획·재고를 보존한다. CONSIDER로 이동하면 체크와 완료 시각을 해제한다.
- 새로 추가할 때 같은 목록·같은 의도의 동일 이름은 기존 수량 병합을 유지한다. BUY의 완료 항목 재추가는 기존처럼 새 입력 수량으로 미완료 복귀한다.
- 반대 의도에 같은 이름이 있으면 자동 변경하지 않는다. ‘이미 고민 중에 있어요’ 또는 ‘이미 살 것에 있어요’ 안내와 해당 보기로 이동을 제공한다. 이 경우 입력은 유지하고, 사용자가 기존 항목을 이동하거나 편집할 수 있다.
- 기본 정보 편집으로 같은 목록 내 다른 행의 이름과 충돌하면 저장하지 않고 기존 항목 확인을 안내한다. 기존 DB에 이미 있는 중복 행은 마이그레이션에서 병합·삭제하지 않는다.
- 수량 범위는 1~99. 합산이 99를 넘으면 조용히 잘라내지 않고 입력을 유지하며 수량 조정을 안내한다.
- 정규화는 기존 공백 정리 규칙을 따른다. 이번 변경에서 대소문자·동의어 통합을 추가하지 않는다.

### 집계·관련 화면

- 구매 진행률 = BUY이면서 완료한 수 / BUY 전체 수. 고민 항목은 분모·분자·‘남은 물건’에서 제외한다.
- 예: 살 것 4, 완료 2, 고민 3 → ‘4개 남았어요 · 2/6 구매 완료’, 고민 중 3.
- BUY가 0이면 진행 막대를 숨긴다. 고민만 있으면 ‘고민 중인 물건 3개가 있어요’로 안내한다. 이를 장보기 완료로 표시하지 않는다.
- BUY가 모두 완료되고 고민이 남으면 ‘살 것은 다 샀어요 · 고민 중 3개’로 표시한다.
- 목록 관리 카드에 남은 수와 고민 수를 별도 표시한다.
- 공유는 기본적으로 BUY의 미완료·완료만 포함한다. 공유 진입점에서 ‘고민 중 제외’를 안내한다. 고민까지 선택 공유하는 기능은 후속 범위다.
- 추천은 의도별로 이미 담긴 항목을 제외한다. 반대 의도의 같은 이름은 위치를 알려 이동·확인할 수 있게 하며 즉시 중복 추가하지 않는다.
- 살림 계획은 기존 ‘모든 품목 보기’를 유지하고 CONSIDER에 ‘고민 중’ 라벨을 붙인다. ‘n개 살 예정’과 확정 구매의 기한 집계에서는 제외한다. 재고·비축 정보는 삭제하지 않는다.
- item_plans는 이름 기준 공통 구매 정보다. 목록별 purchaseIntent를 item_plans에 저장하거나 이름이 같은 다른 목록에 전파하지 않는다.
- 계획 화면의 LazyColumn 키는 실제 항목 `item:<id>`, 독립 계획 `plan:<id>`로 구분하여 두 테이블의 id 충돌을 방지한다.

## 8. 시각 디자인 제안

방향: 차분한 중성 배경, 짙은 초록 포인트, 큰 제목, 가벼운 목록 행. Android 시스템 글꼴을 사용한다.

| 요소 | 라이트 | 다크 / 규칙 |
|---|---|---|
| 배경 | #F6F7F4 | #141A17 |
| 묶음 표면 | #FFFFFF | #1E2722 |
| 본문 | #17251D | #ECF2ED |
| 보조 텍스트 | #59685F | #AFBDB3 |
| 주요 행동 | #176448 | #9CD9B6, 위 글자 #123322 |
| 고민 상태 | #765321 / #F4EAD7 | #E0C38F / #383124; 텍스트 라벨 병행 |
| 구분선 | #DFE5DE | #34423A |

- 제목 30sp/38sp, 품목명 18sp/26sp, 본문 16sp/24sp, 보조 정보 13sp/18sp. 큰 글자 설정에서는 고정 높이 대신 확장·줄바꿈한다.
- 좌우 여백 20dp, 8dp 기반 간격. 개별 행은 기본 64dp 이상, 터치 영역은 48dp 이상이다.
- 카테고리 묶음은 20dp 모서리, 입력창은 20dp, 전환 컨트롤은 부드러운 캡슐형. 모든 요소를 동일한 큰 둥근 카드로 만들지 않는다.
- 헤더·항목에 반복되는 이모지를 줄이고 일관된 선 아이콘을 사용한다. 카테고리 텍스트를 항상 함께 제공한다.
- 상시 그림자를 없애고 표면 차이와 여백으로 구분한다. 시트 등 겹치는 영역에만 필요한 깊이를 준다.
- 체크·이동에 짧은 150~220ms 피드백을 주며 시스템 애니메이션 설정을 따른다. 완료 상태는 흐리게만 만들지 않고 체크·취소선·라벨로 구분한다.
- 입력창과 키보드 인셋을 한 곳에서 처리해 과한 하단 빈 공간과 가림을 방지한다.

이는 제안 토큰이다. 구현 시 실제 대비, 한국어 긴 이름, 시스템 글꼴 크기 200%, 다크 모드에서 확인한다.

## 9. 최신 UI/UX 자료의 적용 범위

2026-09-26 공식 자료 확인. 유행을 그대로 복제하기보다 이 앱의 입력·체크 동선에 맞게 적용한다.

- [Google Material 3 Expressive 연구](https://design.google/library/expressive-material-design-google-research): 색·크기·그룹화로 주요 행동을 찾기 쉽게 하는 원칙. 이 앱에는 하단 입력과 ‘살래요’ 버튼, 콘텐츠 구역 구분으로 적용한다.
- [Android 레이아웃과 내비게이션](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns): 같은 계층 목적지와 화면 내부 전환을 구분한다. 살 것·고민 중은 목록 내부 보기이므로 하단 앱 내비게이션으로 만들지 않는다.
- [Compose 접근성 기본값](https://developer.android.com/develop/ui/compose/accessibility/api-defaults): 48dp 이상 터치 영역, 기본 접근성 역할과 상태를 사용한다.

현재 Compose BOM은 2024.06.00 / Material3 1.2.1이다. 최신 디자인 원칙을 적용하는 것과 최신 Expressive API 도입은 분리한다. 1차 구현에 제품 라이브러리 대규모 업그레이드를 묶지 않는다.

## 10. 데이터 보존과 구현 경계

- Kotlin / Jetpack Compose / Room / Flow의 현 구조, minSdk 26, 오프라인 동작을 유지한다.

- 파괴적 마이그레이션은 사용하지 않는다. v1 → v2 → v3 경로도 검증한다.
- 변경 화면에 필요한 컴포넌트 분리만 수행한다. 저장소 전체의 구조 개편, 계정·동기화·AI 추천·가격 검색·알림·위젯·예산 기능은 포함하지 않는다.
- 고민 이유 메모·고민 항목 자동 이월은 후속 후보이며 이번 기본 설계에는 넣지 않는다.
- 과거 CONTRACT.md의 다른 PC 경로·역할별 파일 소유권은 현재 사용자의 main 작업 지시와 실제 저장소 경로에 맞게 갱신한다. 적용 기술 버전은 실제 Gradle 설정을 기준으로 한다.

## 11. 구현 순서와 완료 기준

1. 화면 시안·전환 방식 확정 → 2. 상태와 마이그레이션 → 3. 바로 입력하는 홈·목록 전환 → 4. 살 것/고민 UI·편집 단순화 → 5. 관련 화면·공유·집계 반영 → 6. 실기기/에뮬레이터 확인.
