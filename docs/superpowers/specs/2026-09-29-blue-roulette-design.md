# 장보기 v1.3.0 — 고민 결정 룰렛과 화이트·블루 디자인

## 의도와 완료 기준

사용자는 고민 중인 물건의 구매 여부를 50:50 룰렛으로 정하고, 결과에 따라 살 것으로 옮기거나 삭제하고 싶다. 초록색 화면은 흰색과 자연스러운 블루로 바꾸고, 휴대폰에 설치할 APK를 받기를 원한다. 계획은 현재 선택 모델로 작성하고 계획 완료 후 GPT-6 Sol, reasoning effort high로 구현한다. 사용자 요청이 계획 후 구현 착수를 명시하므로 별도의 단계별 승인 대기는 하지 않는다. **커밋은 사용자 허락 전에는 절대 하지 않는다.**

이 작업은 기존 Compose 화면과 Room 항목 변경 흐름의 확장이다. 새 서비스, 계정, 네트워크 기능, DB 스키마 변경은 필요하지 않다. 성공 기준은 룰렛 결과·포인터·실제 데이터의 일치, 변경 취소 가능, 전체 화면 색상 일관성, 기존 기능 회귀 방지, 설치 가능한 서명 APK 제공이다.

## 화면과 디자인

디자인 시안: `design/blue-roulette-mockup.html`, 상세 토큰: `design/BLUE_ROULETTE_DESIGN.md`.

- 라이트: 배경 `#F7F9FC`, 흰 카드 `#FFFFFF`, 주색 `#37658C`. 다크: 배경 `#121922`, 주색 `#A6C8E8`. 나머지 Material 색상 슬롯은 디자이너의 상세 표를 적용한다.
- 기존 화면 구조와 타이포그래피를 유지하며 버튼, 선택 상태, 입력창, 진행률, 시트, 대화상자, 메뉴를 일관되게 변경한다. 시스템 다크 모드를 유지하며 동적 색상으로 초록색이 다시 들어오지 않는다.
- 앱 아이콘은 기존 벡터의 모양을 유지하고 블루 계열로 색을 바꾼다. 스플래시와 윈도 배경도 맞춘다. 오류와 삭제 경고의 의미상 빨강은 유지한다.
- 실제 고민 항목은 `ShoppingContent.kt`의 `ShoppingRow`다. 이름/수량/더보기 아래에 `살래요`와 `결정할래요`를 나란히 표시한다. 전자는 직접 이동, 후자는 룰렛이다. 좁은 화면/큰 글씨에서는 가로폭에 맞게 줄바꿈 또는 세로 배치를 허용하고 터치 영역은 최소 48dp로 유지한다.
- 팝업은 둥근 모서리의 작은 중앙 Dialog, 최대 너비 340dp, 기본 룰렛 약 200dp다. 긴 이름은 2줄까지 보여 주며 전체 상품명은 접근성으로 제공한다. 높이가 부족하면 내용 전체를 스크롤할 수 있어야 한다.

## 룰렛 사용 흐름

1. 고민 항목의 `결정할래요`를 누르면 선택 항목명이 있는 팝업이 열린다. 이 시점에는 데이터가 변하지 않는다.
2. `각 50% · 결과에 따라 이동하거나 삭제해요`와 `돌리기`를 표시한다. 시작 전 닫기/뒤로가기는 변경 없이 닫는다.
3. 돌리기 시작 시 난수로 BUY 또는 SKIP을 한 번만 선택한다. 각각의 확률은 1/2이며 반복 횟수를 맞추는 강제 교대나 결과 재추첨은 하지 않는다.
4. 동일 크기 반원 두 개에 `살래요`/`안 살래요`를 표시한다. 고정된 위쪽 포인터 아래에 당첨 섹터가 오도록 약 2.5~3초 감속 회전한다. 회전 시간이나 프레임 수로 결과를 결정하지 않는다. 회전 중 재클릭과 닫기/뒤로가기로 중복 실행하지 못하게 한다.
5. 회전 완료 시 원래 항목을 다시 검사하고 결과를 한 번만 적용한다. BUY는 미완료 BUY 상태로 이동하며 상품명·수량·카테고리·계획을 보존한다. SKIP은 그 장보기 항목만 삭제한다. 기존 별도 보관된 살림 계획/기록은 기존 삭제 정책대로 유지한다.
6. 팝업에 `살래요!`와 `살 것으로 옮겼어요`, 또는 `안 살래요`와 `고민 중에서 삭제했어요`를 보여 준다. 팝업은 사용자가 `확인`으로 닫을 때까지 결과를 보여 주며 다시 돌리기는 제공하지 않는다.
7. 팝업을 닫은 뒤 해당 결과의 실행 취소 Snackbar를 표시한다. 팝업 뒤에서 실행 취소 시간이 지나지 않게 한다. BUY·SKIP 모두 기존 UndoToken으로 정확히 원래 항목을 복원한다. TalkBack 등 접근성 사용자를 위해 충분한 취소 시간을 제공한다.
8. 저장 실패는 성공 결과로 표시하지 않는다. 오류를 보여 주며 같은 결과의 저장 재시도 또는 닫기를 제공할 수 있다. 재시도는 난수를 다시 뽑지 않는다.

## 상태 및 데이터 안전성

- 룰렛 선택/진행/결과 상태를 목록별 ViewModel이 소유한다. Compose 재구성이나 Activity 재생성은 새 난수를 생성하거나 중복 적용하지 않는다. 회전 재생을 다시 시작해도 같은 결과와 같은 세션을 유지한다.
- 프로세스가 종료되면 미완료 룰렛은 취소되어도 된다. DB 반영이 완료된 변경은 보존되며 재시작 후 같은 변경을 다시 수행하지 않는다. 취소 토큰의 프로세스 종료 이후 유지까지는 요구하지 않는다.
- 세션은 항목 ID, 목록 ID, 시작 시점 항목 스냅샷, 결과/목표 각도를 고정한다. 다른 목록/항목에 결과가 적용되어서는 안 된다.
- Repository의 단일 Room 트랜잭션에서 현재 항목과 기대 스냅샷을 비교한다. 항목이 삭제되었거나 이미 이동/수정된 경우 변경하지 않고 오류 상태를 표시한다. 이 검사와 쓰기는 분리하지 않는다.
- 중복 animation-complete 콜백, 빠른 터치, 결과 화면 재구성은 DB에 재적용하지 않는다. 적용 중 취소는 막고, coroutine cancellation을 일반 실패로 삼키지 않는다.
- 결과 안내는 색만으로 구분하지 않고 텍스트 및 접근성 semantics로 제공한다. 애니메이션 배율이 0이어도 결과 적용과 표시가 이루어진다.

## 구현 경계

- 순수 도메인 코드: 결과 선택, 회전 목표 각도와 결과 판정. Compose/Room에 의존하지 않는다.
- Repository: snapshot 검사 + BUY 이동/SKIP 삭제 + 기존 UndoToken.
- ListViewModel: 하나의 세션 생명주기, 중복 실행 방지, 오류 처리, 완료 결과/취소 토큰 전달.
- DecisionRouletteDialog: 표현과 애니메이션. 데이터 저장과 추첨 책임은 갖지 않는다.
- ShoppingContent/ListScreen: 고민 행 버튼 연결, 키보드 닫기, 팝업, 닫은 후 실행 취소 연결.
- 색상은 Theme 및 리소스에 중앙화한다. 불필요한 아키텍처 개편/라이브러리 업그레이드는 하지 않는다.

## 검증과 배포

단위 테스트로 두 결과, 랜덤 선택 단일 호출, 포인터 각도 일치, 세션 중복 방지를 검증한다. Room 계측 테스트로 BUY/SKIP·취소·삭제/수정된 항목·다른 목록·재적용을 검증한다. UI 계측 또는 에뮬레이터 실제 조작으로 idle→회전→두 결과→취소, 취소 전 데이터 무변경, 연속 터치, Activity 재생성, 애니메이션 0을 확인한다. 320/360dp, 글씨 200%, 라이트/다크 화면에서 버튼과 결과에 접근 가능해야 한다.

기존 단위/마이그레이션 테스트, Android lint, debug/release 빌드를 수행한다. versionCode=6, versionName=1.3.0, applicationId 및 DB version=3 유지. 기존 v1.2.0 APK와 서명 인증서가 동일한지 검증하고 업데이트 설치 데이터 유지도 에뮬레이터에서 확인한다. 최종 파일은 `장보기_v1.3.0.apk`, 검증 기록은 `docs/superpowers/verification/2026-09-29-v1.3.0.md`에 남긴다. 실행하지 못한 검증은 명시한다.
