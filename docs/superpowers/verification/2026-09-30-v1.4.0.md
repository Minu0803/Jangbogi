# v1.4.0 마트 홈 릴리스 검증

## 구현 결과
- 첫 화면은 중앙 “어디서 장을 볼까요?” 문구와 마트 일러스트, 마트별 장보기 카드, 고정된 마트 추가 버튼이다.
- 마트 추가/선택 후 해당 마트의 기존 장보기 화면으로 이동한다. 상단 뒤로가기와 시스템 뒤로가기는 마트 홈으로 돌아간다. 마트 이름을 누르면 전환 시트가 열린다.
- 기존 ShoppingList 한 개가 마트 한 곳이다. 기존 ID·이름·품목·완료 상태·고민 중·구매 계획을 보존하며 이름 변경과 삭제 Undo를 제공한다. Room schema 3 유지.
- 추가/이름 변경 시트, 추천 마트 이름, 공백 입력 방지, 중복 제출 방지, 저장 실패 재시도, 마트별 입력 초안 복원을 구현했다.
- 진입/뒤로가기 슬라이드+페이드 280ms, 홈 진입 280ms, 카드 진행률 260ms. 시스템 애니메이션 0 설정에서 동일한 기능을 검증했다.
- 큰 글씨에서는 카드 이름을 별도 세로 영역에 표시한다. 이름을 자르지 않고 스크롤로 접근하며 시트도 키보드/큰 글씨를 고려해 스크롤된다.

계획: `docs/superpowers/plans/2026-09-30-store-home.md`

## 리뷰와 발견된 문제
독립 코드 리뷰에서 저장·선택 중 Activity 재생성 시 이전 화면의 완료 콜백을 호출하는 문제를 발견했다. DB 트랜잭션을 지연시켜 RED를 확인하고, 결과를 ViewModel StateFlow로 보관한 뒤 현재 화면이 한 번만 소비하도록 수정했다. 같은 재현 테스트와 전체 회귀 테스트가 통과했다. 이전에 저장된 긴 이름을 수정할 때 걸리던 입력 길이 제한도 제거했다.

입력 직후 재생성에서 Compose 입력창 종료 콜백이 오래된 버퍼를 전달하는 문제도 로그로 추적했다. 화면 생명주기가 STARTED 이상일 때만 입력 변경을 받도록 고쳐 마트별 초안을 보존했다. 임시 진단 로그는 제품 코드에서 제거했다.

release APK 전체 테스트의 최초 3개 실패는 Compose Dialog 테스트 전용 ComponentActivity가 release에 없기 때문이었다. 전체 26개는 테스트 호스트가 포함된 debug에서 검증했고, 실제 release 앱은 실제 Activity를 사용하는 11개 흐름으로 별도 검증했다. 큰 글씨 테스트의 빠른 스크롤+키보드 이동에 따른 터치 좌표 변동은 접근성 OnClick으로 저장 동작을 호출하도록 테스트를 안정화했다. 제품 코드 변경으로 테스트를 우회하지 않았다.

## 화면과 증거
실제 캡처는 `design/qa/v1.4.0-*.png`에 저장했다. 라이트 기본 홈·빈 홈·추가 시트·마트 장보기·마트 전환, 라이트/다크 320dp·글씨 200%의 홈·추가·전환 화면을 확인했다. 캡처 동기화에는 UI idle 이후 짧은 대기만 사용했다. 실물 휴대폰 및 TalkBack 음성 낭독은 직접 검사하지 않았다.

로그와 JVM 테스트 XML은 `app/build/store-home-verification/`에 보존한다. 2026-09-30 사용자가 `feat: 장보기_v1.4.0 Release` 메시지로 메인 브랜치 커밋을 명시적으로 허락했다.
