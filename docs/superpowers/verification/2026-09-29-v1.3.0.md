- 오래된 항목 스냅샷은 트랜잭션에서 거부합니다. 저장 실패는 오류로 표시하며 재시도 시 원래 결과를 유지합니다.
- 화이트·차분한 블루 팔레트를 전체 Material 슬롯, 다크 테마, 시작 화면, 기존 벡터 아이콘에 반영했습니다.

## 최종 검증 결과

전용 `JangbogiQa` 에뮬레이터(Android 14 / API 34)를 사용했습니다. 사용자 휴대폰 데이터는 다루지 않았습니다.

| 검증 | 결과 |
| --- | --- |
| JVM 단위 테스트 | 43개, 실패 0, 오류 0 |
| Android 전체 계측 테스트 | 17개, 실패 0, 오류 0 |
| 배포할 릴리스 APK의 실제 앱 흐름 | 2개 통과 |
| 시스템 animator_duration_scale=0 | 앱 흐름 2개 통과 |
| 320dp · 글씨 200% · 다크 | 앱 흐름 2개 통과 |
| 320dp · 글씨 200% · 라이트 | 앱 흐름 2개 통과 |
| 실제 v1.2.0 → v1.3.0 덮어 설치 | seed 1개 + verify 1개 통과 |
| lintDebug | 오류 0, 경고 55 — 기존 경고와 동일 |
| assembleDebug / assembleRelease | 성공 |
| 독립 제품 코드 리뷰 | Critical / Important / Minor 지적 없음 |

JVM은 기존 39개 + 룰렛/세션 4개입니다. Android는 기존 이전/일관성 5개 + 트랜잭션 3개 + ViewModel 3개 + Dialog 3개 + 실제 앱 흐름 2개 + 업데이트 fixture 1개입니다.
양쪽 결과의 포인터 일치, 중복 클릭/완료 콜백, Undo 이후 오래된 콜백, 변경된 항목의 보호, 결과 확인 전 Undo 미표시, 재생성 뒤 고민 중 탭 유지까지 검사했습니다.
저장 실패 테스트는 테스트 전용 SQLite trigger로 UPDATE를 중단시켜 트랜잭션 롤백·오류 표시·원래 결과로 재저장·Undo를 검사합니다.

## 화면 확인 및 범위

`design/qa/v1.3.0-*.png`에 실제 화면 캡처를 보관했습니다. 라이트 360dp에서는 홈, 고민 중, 목록 전환, 살림 계획, 편집, 룰렛 준비/회전/결과와 실제 런처 아이콘을 확인했습니다.
라이트/다크 320dp·200% 글씨에서 두 결정 버튼은 세로 배치되며 팝업의 결과·돌리기·닫기·확인은 스크롤로 접근하고 실제 클릭할 수 있습니다.
팝업은 최대 폭 340dp, 화면 높이의 88% 이내이며 큰 글씨에서는 스크롤됩니다. 전체 품목 이름과 확률은 접근성 semantics에 제공하고 결과는 polite live region으로 알립니다.
실물 휴대폰, TalkBack 음성 낭독, 제조사별 시스템 UI는 직접 검사하지 않았습니다. 시안 HTML은 정적 검사했고 실제 화면 검증은 Android 캡처로 수행했습니다.

## 실행 기록과 회귀 수정

- 순수 룰렛/세션 테스트와 최초 Dialog/난수 주입 미구현 RED 기록을 보존했습니다.
- 실제 앱 재생성 테스트에서 기존 ListScreen 진입 effect가 탭을 초기화하는 회귀를 발견했습니다. ViewModel의 selectionEpoch별 1회 복원으로 수정하고 같은 테스트를 통과시켰습니다.
- 마지막 저장 실패 fixture의 첫 방식(db.close)은 Room 재개방으로 Missing을 반환해 의도한 예외를 만들지 못했습니다. 실제 SQL 쓰기 중단 방식으로 바꿨고 최종 전체 17개가 통과했습니다. 제품 코드 변경은 필요하지 않았습니다.
- 추가한 테스트 의존성의 UseTomlInstead 경고 2개를 기존 버전 카탈로그 방식으로 제거했습니다. 의존성 버전은 유지했으며 최종 lint 경고 55개는 기존과 같습니다.
- 전체 테스트/린트/디버그·릴리스 빌드 후 변경된 테스트는 다시 실행했고, 최종 릴리스 설치본의 앱 흐름도 통과했습니다.
